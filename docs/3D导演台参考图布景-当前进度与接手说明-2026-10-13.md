# 3D 导演台参考图布景：当前进度与接手说明（2026-10-13）

> 供新开的 Codex 窗口直接接手。本文记录的是 2026-10-13 本轮结束时的代码、部署与验证状态；不要把早期截图或旧 Worker 版本当成当前状态。

## 1. 当前结论

用户目标是：从一张参考图中识别人物、场景和道具，按同一尺度生成可编辑占位，先预览和校准，再加入 3D 导演台继续摆位、改姿态与排走位。

当前真实链路为：

`单张图片 → 视觉模型输出语义 JSON（components + characters）→ 尺寸/位姿校准 → 几何 primitive + 现有 UE4 角色 → 待应用草稿预览 → applyLayoutDraft 写入正式场景`

这条链路是语义布局估计，不是完整单图 3D 重建。它没有恢复参考相机、逐像素深度、原始纹理、遮挡后几何或原图中的真实 3D 网格。因此“可编辑、比例大致一致、站位与姿态可继续调整”是当前能力；“生成结果与原图完全一致”不在当前实现范围。单图投影、遮挡、尺度估计和模型识别误差仍会造成明显差异。

默认“添加到当前场景”会保留原有对象，并让待应用草稿叠加显示；不会自动清空旧角色或旧道具。浏览器截图中的 `角色01` 是原场景对象，`站立对照`、`坐姿对照` 才是本轮 fixture 草稿/应用对象。若画面显得比原图更拥挤，先检查是否是旧场景与草稿叠加，而不是把它误判成重复识别。

## 2. 本轮已解决的问题

### 2.1 草稿人物改用导演台现有 UE4 角色

此前待应用草稿中的人物由 cylinder/box 几何体拼成，正式应用后才换成真实角色，导致预览与应用结果不一致。

现在预览与正式应用共用 `createLayoutCharacterRenderAdapter`：

- `micro-apps/director-desk/src/editor/schema/layoutDraft.ts:529-560`：统一体型、姿态预设、姿态 controls、旋转、身高缩放和坐姿 root 换算。
- `micro-apps/director-desk/src/editor/schema/layoutDraft.ts:594-604`：正式写入 `DirectorObject` 时复用同一 adapter。
- `micro-apps/director-desk/src/editor/canvas/SceneRoot.tsx:1774-1804`：草稿预览直接渲染 `CharacterModel`，保留选择环，不再绘制人体柱体。
- `micro-apps/director-desk/src/editor/canvas/SceneRoot.test.tsx:285`：验证预览人物走与 apply 相同的角色 adapter。

人物姿态不再只写 `posePresetId`。adapter 会从 `MANNEQUIN_POSE_PRESETS` 复制真实 controls，因此坐姿可以看到屈髋、屈膝；身高也按实际 bodyType canonical height 换算，female 不再错误沿用 mannequin 的 1.86m。

### 2.2 草稿不会因切换人物、道具或相机面板而消失

旧实现会在 `ReferenceLayoutPanel` 卸载时清空草稿。选择正式人物、道具或相机会让右侧面板切换并卸载 ScenePanel，于是用户刚生成的草稿看似丢失。

现在：

- `micro-apps/director-desk/src/editor/panels/ReferenceLayoutPanel.tsx:240-265`：卸载只解绑事件并取消在途请求，不删除成功草稿。
- `micro-apps/director-desk/src/editor/panels/RightPanel.tsx:23-38`：人物、道具和相机面板顶部常驻“待应用布景 · N 组件 / M 人物”入口，点击回到场景面板继续编辑。
- `micro-apps/director-desk/src/editor/panels/ReferenceLayoutPanel.tsx:430-441`：只有成功应用后才清掉待应用草稿。
- `micro-apps/director-desk/src/editor/panels/ReferenceLayoutPanel.tsx:774-781`：提供明确的“添加到当前场景”“替换此生成批次”“丢弃草稿”。
- `micro-apps/director-desk/src/editor/panels/ReferenceLayoutPanel.test.tsx:351`：覆盖卸载后保留、显式丢弃后删除。

“替换此生成批次”只替换对应生成批次，不等于清空整个导演台。取消正在生成的请求也不会删除上一次已经成功的草稿。

### 2.3 草稿按导演台 instance 持久化

`micro-apps/director-desk/src/editor/store/layoutDraftPreviewStore.ts` 当前规则：

- `:4-12`：localStorage key 带 instance scope；持久化语义草稿、编辑状态及组件/人物选择。
- `:46-106`：按 scope 读写并恢复，非法数据或 storage 异常安全降级。
- `:110-171`：`setDraft` 写入当前 scope；`openScope` 切换导演台时恢复对应草稿；`discardDraft` 只删除当前 scope。
- `micro-apps/director-desk/src/App.tsx:210-216`：standalone 首页进入导演台时同步打开草稿 scope。
- `micro-apps/director-desk/src/editor/store/layoutDraftPreviewStore.test.ts:57`：覆盖跨 scope 恢复。
- `micro-apps/director-desk/src/editor/store/layoutDraftPreviewStore.test.ts:87`：覆盖只丢弃当前 scope。

只持久化语义 JSON，不持久化源图 base64、API 密钥或其他秘密。浏览器 storage 写入失败时，当前内存中的草稿仍可继续使用。

本地上传图片由 `ReferenceLayoutPanel.tsx:81-107` 的内存 Map 按 scope 暂存，不跨页面刷新持久化。刷新后可继续编辑和应用已保存的语义草稿，但若要重新调用识别，需要重新选择源图或由宿主重新提供连接图片。

这项修复只能保护本版本之后生成并成功写入 localStorage 的草稿。此前已经被旧版卸载逻辑删除、且没有其他副本的草稿无法恢复。

### 2.4 坐姿 Y 从“座面接触点”正确换算为渲染 root

人物 position 合同已经明确：站立/蹲姿为脚底接触点；坐姿为臀部在座面上的接触投影，`position.y` 是座面高度，通常约 0.40～0.50m。Worker、server 和客户端测试都沿用这个语义。

UE4 `CharacterModel` 外层 transform 的 Y 却是脚底/root 高度。旧 adapter 把坐姿 `position.y=0.45` 直接写成 root Y，导致整个人再被抬高约 0.45m，出现脚底悬空、人物没有坐到家具上的问题。

当前换算：

- `micro-apps/director-desk/src/editor/runtime/ue4Mannequin/ue4MannequinRig.ts:185-194`：基于仓库内置 `public/models/ue-mannequin-retopology.glb`、现有 `sit` controls 和 canonical 体型，记录骨盆座面锚点相对双脚支撑面的原生高度：female `0.4075m`，mannequin `0.4328m`。
- `micro-apps/director-desk/src/editor/schema/layoutDraft.ts:529-545`：只对当前支持的 `sit` 做 `rootY = seatY - seatedAnchorHeight × scaleFactor`；其他姿态保持原位置语义。
- `micro-apps/director-desk/src/editor/runtime/ue4Mannequin/ue4MannequinRig.test.ts:155`：直接读取内置 GLB 骨架并套用当前 sit controls，防止模型、骨骼缩放或姿态预设变化后常量静默漂移。
- `micro-apps/director-desk/src/editor/panels/ReferenceLayoutPanel.test.tsx:328`、`directorStore.test.ts:223`、`layoutDraftPipeline.test.ts:163`：验证座面锚点仍落在草稿给出的 0.45m，而 object root 可以是较低数值。

这项修改修复的是“接触点语义”，不代表解决了完整人物还原或家具识别质量。
