## 个人实践边界

- 默认是现有密码登录下的私有自用，不把服务公网裸露；若将来公开给他人使用，再单独评估账号、项目隔离、存储和协作。
- 本地数据优先用现有导入/导出备份；只有真实遇到容量或性能问题时才考虑 IndexedDB。浏览器存储可能被清理，备份是用户主动动作，不承诺跨浏览器或跨设备自动恢复。
- 视频任务先在本地持久化操作 ID、输入和状态，刷新后恢复供应商轮询；页面关闭时不保证本地继续追踪，供应商任务可能仍在运行。创建超时且没有供应商 ID 时只标“待核对”，不自动重建。
- 不默认增加 D1、R2、Durable Objects、Queues、BullMQ、Redis、独立 GPU/转码 worker、LiteLLM、Langfuse、Yjs、FFmpeg、WhisperX、OTIO 或插件 SDK。它们是遇到具体瓶颈后的可选项。
- 每个获批项都先做一个可在现有画布验证的改动；未获批不实现。相对工作量不代表固定工期。

## 推荐首批小改

推荐顺序：**A04 → A03 → A02 → A05**。它们直接改善已有“生成节点—视频 API—画布”的可靠性和可理解性，不要求新常驻服务。

1. **A04**：在已有视频/TTS/编辑节点上明确真实、模拟、失败和待核对状态。
2. **A03**：为视频提交写入本地操作记录，刷新后能继续轮询，并防止连点重复创建。
3. **A02**：把现有项目导出做成明确备份入口；仅在实际存储压力下增加 IndexedDB 工作区快照。
4. **A05**：用现有镜头字段和节点引用建立最小镜头卡，允许手动标记“待更新”。

首批通过后，优先试 A11（导演台最小回写）或 A06（资产引用备注），按个人实际创作频率选择。每一步单独验收，不自动推进下一项。

## A02 项目、节点、媒体本地备份（缩小）

**已有基础**：`App.tsx:594-611` 的 `readSubCanvasWorkspace` / `writeSubCanvasWorkspace` 及 `:626-779` 使用 localStorage；`components/Settings/ExportImportModal.tsx`、`StorageModal.tsx`、`services/storageService.ts` 已有导入导出入口；媒体可走现有 API 上传路径。

**本阶段做什么**：把导出明确为项目备份，显示最近备份时间/提示；导入前提示覆盖风险。工作区数据接近 localStorage 容量或实际出现卡顿时，才将大快照迁到 IndexedDB，并保留原 localStorage 回退读取。媒体继续使用已有引用，不默认搬运、去重或校验全量历史媒体。

**不做什么**：不默认 D1/R2 数据模型、跨浏览器同步、全量媒体迁移、后台同步、生命周期策略或物理删除。

**验收**：手动导出后可在同一浏览器导入恢复一个项目；导入失败不覆盖当前数据；若启用 IndexedDB，刷新后可读且 localStorage 仍可回退。明确提示浏览器清理数据的风险。

**相对工作量与依赖**：S–M；无 A01 服务端依赖。拟新增，待确认：备份提示、可选 IndexedDB 快照适配。

## A03 视频任务本地恢复与防重复（缩小）

**已有基础**：`functions/api/[[path]].js:927-986` 有 `handleVideoCreate` / `handleVideoPoll`；前端当前以浏览器轮询追踪。

**本阶段做什么**：提交前生成本地操作 ID，持久保存输入摘要、发起时间、provider task ID（获得后）、状态和最近错误；按钮提交中禁用并按操作 ID 防连点。刷新时找回未完成记录并继续轮询已有 provider task ID。

**边界**：页面关闭时本地不保证继续轮询，供应商任务可能仍运行；若创建超时且没有 provider task ID，标为“待核对”，禁止自动重建。供应商不支持取消时，只停止本地后续编排/显示，仍保留状态对账、可能返回的结果和成本信息；不承诺停止供应商计算或退款。

**不做什么**：不建服务端任务库、Durable Objects、Queues、回调平台、exactly-once 或复杂任务 DAG。

**验收**：连续点击只保留一个本地操作；刷新后已有 ID 的任务继续轮询；无 ID 超时不自动重复收费；本地取消后仍能看到供应商最终状态（如可查询）。

**相对工作量与依赖**：S–M；依赖 A04 的状态文案。拟新增，待确认：浏览器任务记录和恢复轮询逻辑。

## A04 真实状态、错误与 Mock 明示（保留）

**已有基础**：`functions/api/[[path]].js:715-730` 的 TTS 无 key 会返回模拟 WAV；视频无配置返回 `VIDEO_API_NOT_CONFIGURED`；`App.tsx:2556+` 有 `[VideoEditMock]`。

**不做什么**：不建适配器健康平台、自动切换模型、交付审批或监控系统。

**验收**：无 TTS key 的结果不能误认真实音频；视频未配置显示可操作原因；A03 恢复任务与节点状态一致。

## A16 单次上下文辅助（缩小）

**已有基础**：现有文本、资产、画布节点和多模型后端可被用户显式引用。

**本阶段做什么**：让用户明确选择少量文本/资产/参考，发起一次“整理镜头计划/改写提示词”的辅助，并把输出作为可编辑文本或草稿节点。既定自用权限内可读资料、写草稿；未授权付费批量提交、超预算或外发才按策略确认。

**不做什么**：不建常驻 Agent、复杂记忆、Langfuse、自动执行计划、隐式全项目检索或自动提交生成。

**验收**：用户选择的资料清单可见；输出引用可追溯；草稿可编辑但不会自动覆盖镜头或发起付费任务。

**相对工作量与依赖**：S–M；可等 A05/A06 的本地字段更稳定后再做。

## A17 团队治理与实时协作（本阶段不做）

个人实践阶段不建设成员、实时协作、Yjs、冲突合并、审批流、供应商对账、财务和权限治理。若未来确有多人共同编辑或公开部署，再从 A01/A02 的实际身份与数据边界重新设计，不复用本版的单人假设。

## A18 性能扩展与观测（后置）

**本阶段做什么**：不做监控平台。只有真实出现卡顿时，先记录复现场景（节点数、媒体数、浏览器、操作）、用浏览器性能工具找热点，再做一个局部优化，例如缩略图延迟加载或长列表过滤。

**不做什么**：不默认引入 Langfuse、指标库、告警、服务端 trace、React Flow 全量迁移或“500 节点”承诺。

**验收触发条件**：可稳定复现并测量的卡顿；优化后同一场景的交互时间有改善且不破坏输入区/画布快捷键。相对工作量：后置，S–M。
